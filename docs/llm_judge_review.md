# LLM-as-Judge self-review checklist

Оценка решения перед сдачей по критериям кейса.

| Критерий | Проверка | Статус |
|---|---|---|
| Соответствие ТЗ | Вход: ВПП, парк БВС, область, тип съемки, ВП, no-fly, резервные площадки | Да |
| Индивидуальные задания | Для каждого активного БВС есть маршрут, высота, скорость, старт, посадка, этапы | Да |
| Экспорт | GeoJSON и KML генерируются через API и UI | Да |
| Минимум два критерия | `min_time`, `min_airtime`, дополнительно `balanced` | Да |
| Веб-интерфейс | Работает в современном браузере на ПК | Да |
| Тестовый сценарий | Есть `examples/demo_scenario.json` и демо в UI | Да |
| Тесты | Покрыты health, планирование, режимы оптимизации, экспорт | Да |
| Документация | Архитектура, алгоритм, запуск, API, ограничения | Да |
| Риск API-ключей | UI без внешних тайлов, не требует ключей | Снижен |
| Практические вопросы из чата | Ограничение времени/дронов, 150 м, камеры, приватность репы учтены в docs/README | Да |

Итог: решение готово к технической экспертизе как полнофункциональный MVP. Основные точки роста для финала: DEM-рельеф, реальная база камер Геоскан, OR-Tools/MILP, интеграция с QGroundControl/Mission Planner.
